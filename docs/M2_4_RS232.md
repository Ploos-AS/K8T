# M2.4 — Four-port RS-232 subsystem

Status: **IMPLEMENTED / HOST-QUALIFIED**

## Purpose

The four serial ports are first-class BBS nodes, not debug headers. Each can independently host a modem, terminal, null-modem peer or other classic serial equipment while Ethernet services and the local console remain active.

## Physical ports

K8T provides four rear-panel DE-9/DB9 male DTE ports using the conventional PC-style DTE pinout:

| Pin | Signal | K8T direction |
|---:|---|---|
| 1 | DCD | input |
| 2 | RXD | input |
| 3 | TXD | output |
| 4 | DTR | output |
| 5 | GND | — |
| 6 | DSR | input |
| 7 | RTS | output |
| 8 | CTS | input |
| 9 | RI | input |

All four ports must support TXD/RXD and RTS/CTS. DTR, DSR, DCD and RI are required at the connector and in the software node/modem model; exact W65C265S GPIO assignment/glue is resolved during schematic pin allocation.

## Electrical layer

The W65C265S UART/GPIO pins are logic-level signals and must not connect directly to RS-232 connectors. Each port uses proper RS-232 line drivers/receivers with charge-pump generation where appropriate.

Transceiver selection is BOM-driven but must provide enough channels for the required data and modem-control signals. ESD protection and connector-side robustness are mandatory for a 24/7 machine.

## UART policy

The four integrated W65C265S UARTs are UART1–UART4. Each port owns:

- independent baud/configuration state
- RX and TX software rings
- modem-control/status state
- independent error counters
- node/session binding
- event wakeups for RX, TX-space and modem-state changes

Baseline supported asynchronous framing is 8N1. Software architecture also permits configurable data/parity/stop modes supported by the hardware.

BBS qualification target is four simultaneous 115200-bit/s 8N1 streams. Classic modem rates remain supported.

## Buffering

Interrupt handlers perform bounded movement between UART registers and software rings. Baseline ring sizes are:

- RX: 1024 bytes per port
- TX: 1024 bytes per port

High/low-water flow-control thresholds are 75%/25%. RTS/CTS is the preferred loss-prevention mechanism for high-rate links. Software XON/XOFF may be implemented at the terminal/node layer but is not a substitute for hardware buffering.

DCD transitions are session-significant for modem nodes. RI/DSR/DTR are exposed so real modem call handling is possible.

## BBS node semantics

A serial port can be configured as:

- modem node
- direct terminal node
- null-modem BBS node
- sysop/maintenance console
- disabled/reserved

The BBS node manager, not the UART driver, owns login/session policy. The driver reports bytes, errors and modem state.

Dropping DCD on a modem-configured node generates a hangup event. DTR can be controlled by the node/modem manager for reset/hangup workflows.

## Fault handling

Framing, parity and overrun conditions increment per-port counters and generate diagnostics without crashing another node. A wedged or disconnected port must not block the scheduler or other UARTs.
